# Projects on an SSH server

Tandem can open a folder on a server over SSH, like VS Code's Remote-SSH, on Windows, Mac and iPad. You edit the server's files in Tandem, and Run and the Terminal run on the **server**, with its Python, as your user there.

⋯ → **Connect to SSH server…** (Windows, Mac and iPad). ⋯ → **Disconnect from …** goes back to the project on this device.

## Two ways to connect

- **As it is (the default): nothing is installed.** The server's own `python3` (3.6 or newer, standard library only) runs [runtime/remote/lite.py](../runtime/remote/lite.py), a small server for the project's files, the **Terminal** and **Run** (the project's `.venv`, or the server's `python3`, with `input()` and Stop). Nothing is downloaded; it starts in about a second. Notebooks, Step through and Debug, Environment and packages, and code completion say they need the full tools.
- **Also install notebooks and the debugger** (a box in the connect window or sheet): Tandem's full runtime, as on a computer: Run, Step through, Debug, notebooks, environments and the Terminal. Installed once per Tandem version in `~/.tandem/remote/<version>/`; after that every connection to that server uses it.

## How it works

1. The app signs in with a password or an SSH key and checks the server's identity (its host key): the first time it shows the key's SHA256 fingerprint to confirm, after that the key must match, or Tandem refuses to connect.
2. It sends [runtime/remote/bootstrap.sh](../runtime/remote/bootstrap.sh) and `lite.py` over the connection (shell commands, no SFTP).
3. With the box ticked, the first time, it installs the full runtime (the app uploads the runtime itself). Its own Python, quickest first:
   - the server's own Python 3.9 or newer (in `PATH`, or where conda, pyenv and Homebrew put it), in a venv: nothing else to download;
   - the same Python without `ensurepip` (Debian and Ubuntu without `python3-venv`): a pinned pip wheel (1.8 MB);
   - no Python 3.9 or newer: a standalone Python 3.12 installed with [uv](https://github.com/astral-sh/uv) (a pinned uv wheel, about 17 MB, then Python, about 30 MB).

   **Where downloads come from.** Packages (about 15 MB) come from the fastest of PyPI and its mirrors in mainland China (Aliyun, Tsinghua, Tencent, Huawei), all tried at once, unless the server's `pip.conf` or `PIP_INDEX_URL` names an index, which is then used. Python for uv comes from the fastest of releases.astral.sh, GitHub and npmmirror. Every file is checked against its sha256, so a mirror can only serve the genuine files: packages are pinned with hashes in [runtime/remote/constraints.txt](../runtime/remote/constraints.txt) (one set per Python version, generated by [runtime/remote/lock.py](../runtime/remote/lock.py)) and installed with `--require-hashes`; uv and pip are pinned in `bootstrap.sh`; uv checks Python's own.

   While it installs, the connect window shows what the server is doing every couple of seconds (what's downloaded, how long it has taken). If the server can't reach any package source, Tandem says so within seconds; a download that stalls (under 1 KB/s for a minute) stops with a message instead of waiting. **Cancel** works at any time: an install already under way finishes on the server by itself, and the next connection uses it (or waits for it).
4. It starts Tandem for the chosen folder (the full runtime if installed, else `lite.py`). It listens on the server's 127.0.0.1 only, with a new random token, and stops when the SSH connection closes.
5. The window shows **Tandem's UI from the app** through a small gateway on this device's 127.0.0.1 (`desktop/ssh/gateway.js`; on iPad the app's local server), which passes only the API and the WebSocket through the SSH connection. The UI's code never comes from the server.

Project code runs with the project's own environment on the server (`.venv`, or the interpreter chosen in Environment), else the server's `python3`, exactly as on a computer.

## Requirements

- A Linux or macOS server with SSH and a POSIX shell (Windows servers aren't supported).
- `python3` 3.6 or newer on the server (almost every Linux and macOS server has it).
- Only for **Also install notebooks and the debugger**, the first time: internet access from the server to PyPI or one of its mirrors (and to GitHub or npmmirror if the server has no Python 3.9 or newer).
- Your account on the server: Tandem installs nothing outside `~/.tandem`.

## Sign-in and what's kept

- **Password or SSH key** (ed25519, ECDSA or RSA, with or without a passphrase).
- Saved servers (address, port, username, folder, key file path) are kept in the app's data, without secrets. A password or passphrase is kept only when you tick **Remember**, encrypted by the operating system (Windows DPAPI, macOS Keychain).
- Passwords, keys and passphrases are typed in the app's own connect window, never in the Tandem page.
- Known servers' host keys: `ssh-known-hosts.json` in the app's data.

## Not on servers (yet)

- **The assistant**: AI keys stay on this device and are never stored on a server.
- **Shared projects (Cowork)** stay a this-device feature.

## iPad

The same, from the iPad app: ⋯ → **Connect to SSH server…** opens a native sheet (saved servers, password or SSH key pasted or picked from Files, the host key confirmed the first time). The SSH client is [Citadel](https://github.com/orlandos-nl/Citadel) 0.11.1 (on SwiftNIO SSH); keys can be ed25519 or RSA in OpenSSH format. Remembered passwords and keys are kept in the iPad Keychain. While connected, the app's local server is the gateway: it serves the app's UI with the server's settings, keeps the iPad layout, and passes `/api` and `/ws` through the connection (`/api/ai` and `/api/shared` stay refused). Python projects on the iPad itself (Pyodide) are unchanged; ⋯ → **Disconnect** goes back to them.

## Tests

- `runtime/tests/test_remote_flags.py`: the runtime's server flags (`--print-token`, `--exit-with-stdin`, `--no-ui`).
- The runtime's whole test suite passes on Python 3.9 and 3.10 (the versions only servers use) with the 3.9 and 3.10 pins of `constraints.txt`, except the assistant's key check on 3.9 (its last Anthropic SDK; the assistant isn't offered on servers).
- `desktop/ssh/ssh.test.cjs`: connection details, host key fingerprints, known hosts, and the gateway (the server's Host and Origin, what stays on this device).
- `runtime/tests/test_remote_lite.py`: `lite.py` with this Python and any in `TANDEM_TEST_LITE_PYTHONS` (checked locally on 3.8, 3.9 and 3.13; `vermin` finds nothing newer than 3.6): host, token and origin checks, files, Run with `input()`, an error and Stop, the Terminal, what needs the full tools, and stopping when the connection closes.
- `ipad/tests/ssh.cjs`: the iPad app in the simulator connected to the CI Mac's `sshd` as it is (Citadel, files sent through shell commands with no SFTP on that server, `lite.py`, the gateway): Run and the Terminal on the server, in the iPad layout.
- `packaging/ssh-e2e.cjs`: the desktop app against a real `sshd` (CI: the macOS runner, with a packaged app; Tandem runs there on the server's own Python 3.9, macOS's `/usr/bin/python3`): host key confirmation; connected as it is (`lite.py`, nothing installed): Run, the Terminal, notebooks asking for the full tools; Disconnect (Tandem stops on the server); a key sign-in with **Also install notebooks and the debugger**: Step through and a notebook cell; and a changed host key refused.
